# 最小整合计划、风险与发布门槛

## 1. 范围与顺序

起点：云端 `4a137bbf05bb192e488c79ab9954027e05c9bc50`。待吸收功能：`9c638df774c22252ed1b7d25a9dcf9e930fdfe8c`。本轮只在云端开发和验收，不进行 GitHub 上传或生产操作。

1. 记录基线、工作区状态与待整合差异；在新候选中逐项应用功能，不能用远端旧文件覆盖云端完整文件。
2. 保留开关默认 `false`，配置样例明确不确定结果重试风险。配置、文档和测试保持同一键名与默认值。
3. 分类器只在真实上游 HTTP 400 且 body 为有效 JSON 时读取 `error.code`、`response.error.code`、`code`。去首尾空白后必须精确等于 `image_poll_timeout`，不做大小写折叠或子串猜测。
4. 在既有 Images 错误处理顺序中，先尊重管理员 passthrough、账号错误码策略、OAuth 主控模型拒绝，再考虑新开关。此顺序针对该特殊分支；其他已有独立 failover 路径不被关闭或重新定义。
5. 特殊分支保留上游状态 400，返回 `(nil, UpstreamFailoverError)`，原因 `openai_image_poll_timeout`，不允许同账号重试；交由已有失败账号排除、账号切换及 transient cooldown 机制处理。
6. 新原因仅在图片 Smart Router 报告中映射为 timeout；生成、编辑及文本各自能力/模型健康键保持原语义。日志和持久健康摘要不得因新增分支写入任意上游原文。
7. 适配云端 `ReportSmartRouterImageResult(requestCtx, ...)`、`ReportSmartRouterTextResult(ctx, ...)` 签名。远端无 context 参数的测试不能原样复制；不得移除请求取消/截止检查来消除编译错误。
8. 完成 [TEST_MATRIX.md](TEST_MATRIX.md) 的定向证据及最终组合源码的聚合门禁，独立检查差异与收据，再制作离线验收包。

### 不扩大设计

继续使用既有上游 API/Responses 适配、调度、并发槽/保留资源、错误响应、usage 记录和健康持久化；不引入自行设计的任务队列、轮询协议、远端取消、幂等协议、跨尝试费用合并、新收费项目或 schema。若需要更小的“轮询超时专属重试预算”，单独评估和批准，不悄悄改变本次最小整合的全局重试语义。

## 2. 必须保留的云端修复

- 请求总预算覆盖选择与所有尝试；独立上游尝试限时和用户取消必须能终止后续调度。保留“截止时间已过但 timer 尚未投递”的判断。
- 已输出真实内容后不再切号，不丢弃已产生图片；whitespace keepalive 的特殊计数和已提交 HTTP 状态遵循现有边界。
- 可重试 nil-result 尝试不单独提交本地 usage；后续成功沿既有路径结算一次。终止、不可重试且确有可信用量的流式/非流式失败仍按原计量规则处理。不能将上述规则写成“所有失败都不收费”。
- 不新增失败尝试用量聚合，不凭错误 body 推测图片数/用量。余额、订阅及现有计价链路保持原样。
- 用户取消和请求总预算耗尽不能成为新的 Provider 健康惩罚来源；图片能力隔离和安全健康摘要不倒退。
- 保留单 tracker/key 健康投影尝试顺序、旧事件时间戳单调更新、Restore token 与既有 sink 时间预算。它仍是 best-effort，不是分布式 exactly-once。
- 不用旧 lint 版本或放宽规则绕过工具链问题；保留云端已配置的资源约束和工具版本。

## 3. 风险与决策

| 风险 | 现有机制/限制 | 本轮要求 |
| --- | --- | --- |
| 上游已经生成但轮询超时，重试产生重复图/重复 Provider 费用 | 没有远端任务取消、查询对账或幂等保证；本地只结算一次不能证明 Provider 只收费一次 | 默认关闭；启用前明确风险承担者、有限真实验证预算和对账方式；不能靠 mock 宣称已消除此风险 |
| 重试次数/耗时比“重试一次”大 | 加载默认 10 次切换，最多 11 个不同账号尝试；单次上游 180 秒、全请求 600 秒，任一限时设 0 表示禁用；构造器切换兜底 3 | 测试排除集和上限；启用前核查实际部署值，禁止把理论次数误称为保证次数；如不接受风险则保持关闭或另立更窄预算设计 |
| 共享账号文本可用性下降 | cooldown 调用账号级 `BlockAccountScheduling` 和 `SetTempUnschedulable`；生成基值 30 秒、编辑 12 秒，错误率倍率最高 8，既有总上限 10 分钟 | 同时验证健康能力隔离与账号调度影响；运营确认共享池是否可接受，必要时使用已有独立账号/分组方案 |
| 误判普通用户错误或覆盖管理员意图 | 新分类很窄，但已有较广 failover 开关/路径仍独立有效 | flag off/on、语义近似、HTTP200 SSE、passthrough/账号/OAuth gate 反例必须有证据 |
| 复用旧源码覆盖云端计量、取消和健康顺序修复 | 存在共同改动文件和已知 context 签名差异 | 手工保留双方必要改动；编译、计数计费、取消/输出和 health regression 必测 |
| 交付材料把旧测试冒充新候选通过 | 上轮代码 SHA 与本轮组合代码不同 | 冻结最终代码，记录起止 SHA/tree、工作区、命令、环境、退出码及日志 hash；代码再变则重跑相关门禁 |

本地扣费/usage 计数测试证明的是受控输入下本服务的调用与结算行为，不是 Provider 合同、真实金额或真实任务状态。

- 构建身份绑定受测代码；后续文档提交如不同，分别记录。旧前端证据只有在相关源码和锁文件字节未变时才可标为历史复用，不称本轮重跑。
- 离线包核验基线依赖、导入 HEAD/tree、文件清单、hash、文档链接及无敏感配置；提供最终收据，停在 GitHub 上传之前。

1. 用户另行授权上传/发布；随后检查实际远端候选 SHA 的 CI、安全扫描和发布流程。云端通过不能代替 GitHub CI。

3. 真实 Provider 测试须单独授权凭据使用、请求数据、提供方及花费上限。覆盖生成/编辑和实际使用的 API-key/OAuth 路径，保存经过脱敏的请求/任务关联和账单证据；不上传密钥、原始私有提示词或图片作为一般测试日志。
