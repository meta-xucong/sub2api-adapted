# 发布边界与兼容条件

此轮只修复指定 PR 的可证实缺陷；以下条件不能用单仓库单元测试替代。

## 桥接权限与身份

- 浏览器的 `login-ticket` 只能从原生 JWT 中间件写入的已验证 subject 获取 user ID；请求中的自称 user_id 不成为身份来源。
- 共享 internal token 是可信后端服务的跨用户权限，覆盖兑换、账户/用量读取和扣费。它没有证明“消费端只能操作刚登录的某个用户”。不应给浏览器、插件、不可信租户或其他第三方。若产品要求消费端彼此不信任，当前协议不满足，需另行审批用户/服务作用域设计，不能将本 PR 当作解决方案。
- 不采集或回显生产 token。部署前由操作者核实足够熵的随机生成、只存在服务端秘密配置、文件权限、TLS、出站目标限制和日志脱敏；不要因测试 token 可用就判定生产秘密安全。
- 保留旧 Video 仅提供 ticket 的兑换契约。响应 intent 必须由每个消费者严格匹配其固定预期。Alchemy 与 Video 的实际部署版本、Origin/CSRF 防护、返回身份到本地会话的绑定均须独立验证。
- 兑换时重新校验账号存在/active，只解决停用/删除窗口。已签发短期票据没有绑定原 JWT TokenVersion/session ID；密码修改或单会话撤销后的票据撤销传播不能宣称完成。不得擅改原生 AuthSubject 或外部票据字段来掩盖该限制。
- 失败关闭会消耗已经领取的票据，防止瞬时账号查询失败后再利用同一票据。用户应重新登录获取新票据。账号状态检查与消费者建立会话之间也不构成跨系统原子事务。

## URL 转存、代理与图片边界

- 图片 URL 转存使用受控公共 IP 拨号；环境代理生效时拒绝。某些仓库层下载也拒绝账号代理。没有目标部署 HTTP_PROXY/HTTPS_PROXY/NO_PROXY、账号代理与上游返回格式证据，不能判定现有部署兼容。
- 不静默绕过管理员代理，不用普通代理下载替代 IP 绑定。必须代理且返回 URL 的部署保持阻塞，直到验证受信代理的目的地址防护或确定支持的直连路径。NO_PROXY 变更属于部署决策，本轮不操作。
- base64 图片不需要 URL 下载；对象存储不开启时透传。具体调用链仍应在隔离部署中分别验证。PNG/JPEG/GIF/WebP、单轴、总像素及32MiB压缩字节上限均为有界策略，不等于支持全部媒体格式/尺寸。

## 财务留存与上游费用

- 成功扣费回执与余额变更同事务，重放匹配 user/amount/source/reference，不匹配时冲突。必须让所有正在运行和可回滚版本的清理器保留该财务 scope。
- 不自动清理成功回执，不在此轮做未经授权的保留期变更。长期增长需测量行数、表/索引体积及备份增长；任何归档必须继续保持唯一幂等判定，不可先删再导。已有删除的历史回执不会自动恢复。
- receipt 保存 source/reference 不能替代完整财务检索产品。是否需要逐笔 source/reference 查询、保留期限和对账导出，由财务确认；本轮不新增账本或财务接口。
- 取消、超时或网络中断可能发生在上游已受理之后。切换/重试可能重复生成并产生上游费用，本地用户扣费幂等不保证上游 exactly-once；真实费用需独立对账。

## 测试结论

只依据最终候选的新执行收据评估。生产、真实 Provider、消费端未验证项标为 INSUFFICIENT_EVIDENCE。没有证据支撑“所有功能绝不受影响”或“无任何漏洞”的结论。

## LastResort 冷却原因的明确范围

沿用 `core/health.go` 现有分类，不恢复 timeout 专用开关。仅明确的图片选号进入最后兜底：普通能力失败产生的 capability quarantine、auth quarantine、rate-limit cooldown、stream-interrupted cooldown/quarantine、普通 transient/sustained-failure cooldown，只有最终状态仍为 `RecoveryCooling` 且所有原生资格检查通过时才可能候选。原生已禁用/凭据失效/配额/组别/模型/并发等硬门禁不能因这个枚举而跳过；`RecoveryModelUnavailable` 继续禁止。`FailureCancelled`、请求/负载错误不新增健康惩罚；图片内容拒绝使用原软跳过语义，并非本次新增恢复状态。此范围是既有广义故障恢复策略，不是“仅上游 image_poll_timeout 才允许最后尝试”。
